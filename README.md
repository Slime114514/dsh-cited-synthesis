# 一丝不苟 · 检索交付规范

> 让 AI 的每次搜索都按论文的标准来。

给 DeepSeek Harness 加一条默认规则：**凡是联网检索得出的答案，都要带能核对的链接、写清成立条件、把相反结论摆出来。**

不改变模型能做什么，只改变它怎么交付。

**已知问题：回答会变长。**

## 它做什么

安装后向 profile 注册两样东西：

| 注册项 | 作用 | 什么时候生效 |
|---|---|---|
| system prompt 段落 `cited-synthesis-rules` | 九条硬约束，每次都出现 | 每一轮 |
| skill `cited-synthesis-delivery` | 完整流程：证据台账、条件维度、分歧三步判定、交付模板、交付前自检、反模式 | 模型按需加载 |

段落只占约 200 token，长文本全部放在 skill 里，避免每轮付费。

九条约束是：

1. 实质结论后跟链接，链接必须直接支持该句；数字转引自某篇综述时，写明转引自哪里。
2. 先分清断言类型：可观测事实 / 制度性事实 / 权威建议 / 争议判断 / 自身建议；自身建议必须标 `[推断]` 或明说"我的建议"。
3. 写成"条件—结论"，来源没说条件就写"条件未说明"。
4. 主动找反例，相反结论按条件并列。
5. 标注证据类型（官方 / 同行评审 / 预印本 / 厂商自述 / 媒体）。
6. 跨来源拼接、因果归因、跨研究排序、一句话总括、把关联转成处方，都标 `[推断]` 并写依据；总括若只是压缩下文已标注的结论，可省。
7. 分级代码（证据等级 2a、GRADE）要么当场解释，要么不用。
8. 结尾列未核实项与检索范围。
9. 篇幅与"决策代价 × 真分歧"成正比；事实一句带过，建议必须带归属。

## 安装

官方 CLI：

```sh
npx @deepseek-ai/dsh web
```

在插件管理器里安装 `dsh-cited-synthesis`。也可以直接用 `plugin_manager` 的 `install_bundle`：

```
target: dsh-cited-synthesis@0.2.1
```

开发时 `target` 也可以传本地目录的绝对路径。

本包是 Host-only bundle，无运行时依赖，不需要构建步骤，没有安装脚本。

## 效果边界

- 它保证模型**每次都看到**这条规则，不保证每次都照做。提示词不是校验器。
- 链接是否真的支持那句话，最终仍要人判断。真正做逐句核验需要额外的管线，不在本包范围内。
- 与"平衡"有关的取舍：证据一边倒时，规则要求如实说一边倒，不要为了对称硬造反例。强行五五开本身是一种失真。
